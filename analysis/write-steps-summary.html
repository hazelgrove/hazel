Hazel Write Steps Implementation Summary

This document is the current implementation map for write-steps, math automation, Algebrite suggestions, and Coq/Rocq export. The long historical roadmap was intentionally removed; the standalone thesis roadmap remains in analysis/thesis-proposal-roadmap.html.

Typed steps Users can write the next expression and have Hazel check it.
Level-gated math Arithmetic, Algebra, and Trigonometry are active levels.
Export traces Accepted steps carry prover-oriented summaries when available.

Current State

The branch turns the missing-step overlay into a small math workbench: choose a math level, choose an automation stage, write or select a candidate step, then store a proof step with a justification and export metadata.

  • WrittenStep, rewrite suggestions, auto simplifications, and proof-search candidates all flow through the same stepper replacement path.
  • Axioms.re is the source of truth for math levels, automation stages, rewrite groups, rule ids, and prover hints.
  • RewriteChecker.re owns normalization, equivalence checks, trace summaries, and prover-step breadcrumbs.
  • Coq/Rocq export replays stored prover steps where they exist and falls back to labeled tactic groups for coarser proof-search macros.
Historical note: the earliest written-step checker only compared against Hazel evaluator next steps. The current checker is level-aware and can accept normal-form equivalence, guarded rewrite targets, or bounded Rocq search results.

Checker Pipeline

The stepper separates the math level from the automation stage. The level controls which objects and rules are legal; the stage controls how much help Hazel provides.

One step Show explicit rewrite targets and manual actions for a selected expression.
Check result Compare the written target using the checker for the selected math level.
Auto simplify Offer local simplification targets that Hazel can justify.
Proof search Ask bounded JSCoq/Rocq tactic search to validate a candidate target. 
selected expression + user target
  -> level gate in Axioms.re
  -> RewriteChecker normalizer or rewrite target
  -> trace_summary with rule ids and prover_steps
  -> StepperBase stores the accepted proof step
  -> CoqProofExport replays or validates the trace

Math Levels

Levels are cumulative by rank. A higher level can use lower-level operations, but export should still pick the smallest tactic group that matches the actual subgoal.

Level Status Allowed work Default Rocq group
Arithmetic Active Constants, affine terms, adjacent arithmetic steps. hazel_arithmetic
Algebra Active Distribution, factoring, cancellation, polynomial normal forms. hazel_algebra
Trigonometry Active Sin/cos/tan identities plus arithmetic and algebra around them. hazel_trigonometry
FunctionsAndLists Planned Unfold, beta, map, fold, and induction helpers. Not implemented
Calculus Planned Derivative, limit, and domain-specific theorem groups. Not implemented

Construct gating rejects expressions that require a higher level, such as trig calls in Arithmetic mode or unknown function calls before the Functions/lists level exists.

Capabilities

Arithmetic

  • Affine normal form: constant plus sorted symbolic coefficients.
  • Accepts examples like 3 + x == x + 3 and 2 * x + 3 == x + x + 3.
  • Rejects non-affine symbolic products like x * x.
  • Manual one-step recognizes adjacent addition swaps and constant folds as exportable rules.

Algebra

  • Polynomial normal forms cover products over sums, small powers, coefficients, and like-term collection.
  • Rewrite targets cover distribution, reverse distribution/factoring, cancellation, binomial/trinomial expansion, conjugates, and completing simple squares.
  • Current weakness: some associativity/flattening behavior is still presentation-driven rather than a single canonical UI model.

Trigonometry

  • Bounded identity search covers selected sin/cos/tan transformations and double-angle style rewrites.
  • Algebra-only subgoals under trig expressions should export through the Algebra tactic group when trig calls are unchanged.
  • Scalar simplifications inside trig arguments, such as cos(2 * (2 * x)) -> cos(4 * x), are handled as prover-searchable steps.

Algebrite Status

Algebrite is not the trusted written-step arithmetic checker. It is currently used as a suggestion source and retained for legacy step compatibility.

  • The UI button is labeled simplify with algebrite and seeds the written target editor with one candidate simplification.
  • The candidate is checked by the same Hazel/Rocq path as if the user had typed it manually.
  • Export should depend on the accepted Hazel trace or Rocq tactic summary, not on trusting Algebrite.

Coq/Rocq Export

There are two related paths. Browser JSCoq validates candidate steps during editing. File export renders a complete Coq/Rocq proof from the stored stepper chain. A mismatch between these paths is a bug.

Part Role Current policy
ProofSearchBackend.re Builds bounded tactic-search programs. Chooses the export level from the subgoal, not only from the UI mode.
CoqExport.re Renders Hazel expressions into Coq/Rocq terms. Chooses integer or real prelude based on the whole proof context.
CoqProofExport.re Replays stored proof steps. Uses local assertions for breadcrumbs and labeled tactic fallbacks for macros.
window.HazelJSCoq Browser-side checker. Should reuse managers when possible, but cleanup must not crash JSCoq logging.
Export still contains coarse tactic fallbacks for some macro steps. The next quality bar is to lower more accepted UI actions into primitive prover breadcrumbs, especially algebra normalization and hidden associativity/commutativity steps.

Rocq tactic groups by math level

Math levels are the policy source of truth, but the exported tactic group is chosen from the actual checked subgoal. This matters when a Trigonometry-mode expression contains an algebra-only rewrite, such as distributing around unchanged cos(...) calls.

Effective level Macro rule id Rocq tactic group Current scope
Arithmetic rocq.arithmetic_tactic_search hazel_arithmetic Linear arithmetic, constant folds, simple numeric cleanup, and bounded rewrite search.
Algebra rocq.algebra_tactic_search hazel_algebra Arithmetic plus distribution, factoring, polynomial-style expansion, cancellation, and scalar-product simplification.
Trigonometry rocq.trigonometry_tactic_search hazel_trigonometry Algebra plus supported sin/cos identities, half-angle rules, double-angle rules, Pythagorean rules, and trig argument algebra.
FunctionsAndLists, Calculus Reserved macro ids Not active as user-facing groups These levels are disabled until they have their own rule groups, proof rules, and export tactics.

Per-step JSCoq checking and export automation

The intended flow is proof-producing even when the UI shows a single button press or a collapsed automation result.

  1. Axioms.re defines the cumulative math levels, automation stages, rewrite groups, rule ids, and prover hints.
  2. ProofSearchBackend.effective_level_for_request lowers a requested level to the smallest sound export group for the subgoal. In particular, Trigonometry and Calculus requests whose trig applications are preserved export as Algebra subgoals.
  3. ProofSearchBackend.rocq_search_program renders a one-theorem JSCoq/Rocq check with the inferred integer or real domain and the selected tactic group.
  4. If browser JSCoq accepts that theorem, Hazel stores a collapsed trace_summary with the macro rule id and a prover_step. Algebrite suggestions use the same path: Algebrite only proposes the target; Rocq/Hazel still validates it.
  5. File export replays stored prover_steps as local Coq/Rocq assertions, then rewrites them into the final theorem. When a step has no fine-grained breadcrumbs, export falls back to the recorded tactic group rather than guessing from the visible UI mode.
  6. Generic cleanup steps are domain-aware: integer cleanup uses the bounded integer rewrite fallback, while real cleanup uses hazel_arithmetic so facts like 2 * 1 = 2 in R do not fail export. 
selected source + candidate target
  -> Axioms level gate
  -> effective export level from the subgoal
  -> JSCoq theorem using hazel_arithmetic / hazel_algebra / hazel_trigonometry
  -> accepted trace_summary with rule ids and prover_steps
  -> CoqProofExport local assertions or tactic-group macro
  -> local coqc and browser JSCoq should agree

Known Gaps And Priority TODOs

  1. Finish the associative flattening design for presentation and selection. Avoid eager unparenthesize behavior that treats a descendant selection as if the parenthesized expression itself was selected.
  2. Convert more algebra targets from coarse macro summaries into replayable primitive prover steps.
  3. Keep local coqc export checks and browser JSCoq checks aligned. If one passes and the other fails, track it as an export bug.
  4. Add repeatable browser regression coverage for JSCoq cleanup, logging, timeouts, and manager reuse.
  5. Implement Functions/lists only after the arithmetic and algebra export traces are stable.
