Arithmetic and one-step mode
----------------------------

Open impressions:
- We do not have any axioms written yet to use in "Assumptions". Is that the
  correct place for user-visible manual arithmetic rules?
- We should disable or narrow the legacy rewrite checker button because it can
  still let users take steps that are too large using Algebrite-style checking.
- A single eval-step fill-in box is probably fine if it permits only one
  exportable rule. Example: allow `1 + 2 + 3 + 4` to `1 + 2 + 4 + 3` as one
  commutation, but not `2 + 1 + 4 + 3`, because that requires two commutations.

Implementation interpretation:
- "One step" should mean exactly one trusted rewrite/evaluator rule with an
  export target.
- The UI can still let the user type the result, but the checker for this mode
  should reject changes that require multiple rewrite records.
- The rule source should move toward `Axioms.re` records with prover metadata,
  not opaque CAS simplification.
- Export architecture should stay prover-agnostic: Hazel records ordered
  rewrite steps once, then Coq/Rocq and Lean backends render those same steps.
- If the current "Rewrite" button remains available in one-step mode, it should
  use the same one-rule checker rather than broad equivalence.

Arithmetic and Check result mode
--------------------------------

Open impressions:
- This mode is good as-is for exploration, but before theorem-prover export we
  need to make sure exportable rules and axioms line up with the accepted normal
  form equality.

Implementation interpretation:
- Check result can continue to compare normal forms and accept multi-step
  equivalence.
- The accepted equivalence must return a trace summary that can later be
  expanded into replayable trusted rewrite records.
- This mode should be labeled clearly as "compare normal forms", not as a
  single proof step.
- For theorem-prover export, the trace summary is not enough by itself. It must
  eventually become a replay tree or sequence whose leaves are trusted rules.
- Current no-`ring` Coq/Rocq export is a demo of primitive rewrite replay plus
  bounded search. It should become an ordered Hazel trace that can also render
  to Lean.

Handled:
- 2026-06-10 00:20 EDT: The written-step checker already stores a trace summary
  for accepted arithmetic/check-result steps. This is a useful placeholder, but
  it is not yet a replayable proof export.
- 2026-06-10 12:48 EDT: Added an `algebra` rewrite group with placeholder
  distribution, factoring, and additive-cancellation rule metadata. Algebra
  remains disabled in the UI until these rules are backed by real checkers.
- 2026-06-10 12:48 EDT: Added the first executable algebra checker for
  distribution and reverse distribution/factoring at `Algebra` level. It accepts
  `x * (y + z) = x * y + x * z` and the reverse direction, but it does not yet

- 2026-06-10 13:01 EDT: Extended the algebra distribution/factoring checker to

Arithmetic and Auto eval
------------------------

Open impressions:
- Make sure the simplification procedure follows a good process and builds a
  tree of exportable rules for the proof export at the end.

Implementation interpretation:
- Auto eval should be normal-form driven, but the hidden work cannot stay as one
  opaque "simplify" step.
- The simplifier should produce both the final expression and a derivation:
  before/after nodes, applied rule ids, source spans or selected subterms, and
  theorem-prover hints.
- The UI can hide this trace by default, but "show hidden steps" or prover
  export should be able to reveal it.
- The derivation format should be shared with Check result so both modes export
  through the same trusted path.

Handled:
- 2026-06-10 00:20 EDT: Auto eval currently reifies the affine normal form and
  inserts an `AutoSimplifyStep`. It does not yet persist the hidden rewrite tree
  needed for theorem-prover export.
