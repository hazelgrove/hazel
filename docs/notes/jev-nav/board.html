Inside one Jev view request

  1. Agent asks in words: modify_view("fuel charge, idle penalty…")
  2. Hazel lists every definition with its path + code (61 on the fleet program, ~11k tokens)
  3. Paths named in the request open directly — Jev isn't asked about those
  4. For each path (e.g. Fuel/fuel_cost), Jev answers: expand it or keep it folded? Asked as Must the agent read or change Fuel/fuel_cost to do this? — all paths in one batched call
  5. Jev returns P(yes) for each → "yes" = P > 0.5 (Jev's own call, no extra cutoff)
  6. Hazel opens the yes-set + their parent modules (a folded parent would hide them)
  7. Added to the current view (or replaces it if the agent asked for a reset); everything else stays folded ⋱
  8. Agent sees the new view on its next turn

Inside one Jev code request

  1. Agent calls jev_edit(path, goal, names) — no code, just the spec
  2. Hazel starts from one ? hole and lists what can legally go there (right type, in scope, code shapes, + agent's names/numbers)
  3. Jev picks one option per hole (multiple choice), holes batched
  4. Hazel rejects any pick that adds a type error
  5. New holes from the pick (e.g. if ? then ? else ?) → repeat, up to a round limit
  6. Unsure or no valid option → hole handed back to the agent
  7. Agent sees the result and any open holes
