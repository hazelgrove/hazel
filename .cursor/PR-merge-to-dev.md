# PR: merge into `dev`

- Agent Context panel renders the program under `<agentEditorView>` with the same read-only Hazel segment view used for tool-result diffs in chat (live editor + collapse rules), with the rest of the context message still shown as text below.
- Chat bottom bar shows last-response `prompt_tokens` vs OpenRouter `context_length` with a themed progress bar and hover tooltip (fraction to six decimals); model list parsing stores optional `context_length` on each LLM.
- **Read-only folds:** `CodeViewable.view_segment` passes an empty `shape_map`, so fold projectors used to render as blank. When `kind == Fold` and `shape_map` is empty, we render the same **⋱** glyph and fold styling as `FoldProj`; the full interactive fold projector UI is not used in read-only unless we later wire projector shape/measurement there.
- **Slash commands:** Typing `/` opens a palette (filter, arrows, Enter); **`/compact`** runs the same compaction path as auto token-limit compaction. Styles in `agent-chat-messages.css`.
- **Compaction:** `CompactionPrompt.re` holds the long compaction summarizer system text (alongside `CompositionPrompt` in `prompt_factory/`). The compaction API call includes a **truncated copy of the live agent system prompt** plus **developer notes**, and appends a **final `<context>` message** built like production (`<agentEditorView>`, static errors, test results, workbench) so the summarizer sees the current program **without changing the editor UI**.
- **OpenRouter:** Assistant message `content` may be a JSON array of `{ "text": ... }` parts; parsing now handles that (and optional `reasoning`) so compaction and chat do not get empty replies when the provider returns array-shaped content.
- **UI:** “Compacting conversation…” banner is rendered at the **bottom** of the chat log (above the composer) instead of the top.
